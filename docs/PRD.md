## 1. 项目概述

### 1.1 项目背景

**核心问题**：散户做波段/中频股票投资时，面临信息过载、决策碎片化、情绪干扰三大痛点。

- 信息来源分散：新闻、行情、公告、社交媒体，每天数百条，筛选成本高
- 决策缺乏系统：买入/卖出往往是直觉或跟风，缺乏结构化分析流程
- 情绪干扰严重：贪婪/恐惧主导，容易追涨杀跌，错过真正的机会

这是一个个人使用的A股交易辅助系统，通过多 Agent 协作分析市场，辅助投资决策。

### 1.2 目标用户

- 有一定投资经验的个人投资者（非小白）
- 持仓规模 10万-100万，关注波段机会而非高频套利
- 时间有限（上班族），希望高效获取决策建议

### 1.3 项目定位

- **个人工具**：不考虑高并发、复杂异常处理
- **模板项目**：代码结构规范，可作为其他用户的参考模板
- **教育目的**：展示 LangGraph 多 Agent 系统的最佳实践

---

## 2. 核心价值

**一句话**：一个帮散户做波段投资决策的 AI 系统，通过多 Agent 博弈机制，让决策更理性、更系统。

**核心能力**：
- 信息过滤：从海量新闻中筛选真正相关的（TrendRadar MCP）
- 多视角分析：技术面 + 基本面双轨并行
- 博弈决策：买卖双方辩论，最多 10 轮深度辩论
- 归因分析：解释决策的因果链（A→B→C→D→E）
- 反事实推断：分析假设下跌场景的影响
- 持仓联动：结合已有持仓状态给出建议

## 3. 核心功能

### 3.1 市场分析功能

**目标**：分析A股市场整体形势，识别投资机会。

**分析流程**（4 节点线性）：
1. **宏观分析**：判断当前市场是牛市/熊市/震荡市
2. **板块分析**：识别热点板块（如AI、新能源、医药等）
3. **行业分析**：深入分析热点行业的增长潜力
4. **个股筛选**：从热点行业中筛选出有潜力的个股

**输入**：无需特定输入（自动获取市场数据）
**输出**：
- 市场形势判断（牛市/熊市/震荡）
- 热点板块列表（Top 5）
- 推荐个股列表（Top 10，含简要理由）

### 3.2 股票分析功能

**目标**：分析具体股票的投资价值，给出买卖建议。

**分析流程**（9 节点含辩论循环）：

1. **初始化节点**：
   - 系统检测：检查 API 连接、数据源状态
   - 持仓加载：读取当前持仓配置

2. **基本面分析**：
   - 财务数据（营收、净利润、ROE等）
   - 行业地位
   - 公司治理
   - 风险评估
   
3. **技术面分析**：
   - K线形态
   - 均线系统
   - MACD、KDJ等指标
   - 量价关系
   - 资金流向
   
4. **数据汇总节点**：
   - 合并技术面 + 基本面分析结果
   - 计算综合评分
   - 提取关键论据（供辩论使用）
   
5. **辩论环节**：
   - **BullAdvocate（买方）Agent**：列举买入理由
   - **BearAdvocate（卖方）Agent**：列举卖出/观望理由
   - 双方进行辩论，互相反驳
   - **辩论评分**：论据质量评分
   - **提前终止**：连续5轮无新论据则停止
   - **最大轮数**：10轮
   
6. **决策环节（Judge Agent）**：
   - 综合辩论结果，做出最终判断
   - **归因分析**：解释买入/卖出的因果链
   - **反事实推断**：分析假设下跌场景的影响
   
7. **持仓建议**：
   - 买入/卖出/观望
   - 建议仓位（考虑当前持仓）
   - 止损位、止盈位
   
8. **飞书推送**：
   - 格式化决策报告
   - 推送到飞书 Webhook

**输入**：
- 股票代码（如：600036）
- 当前持仓（人民币金额，0表示未持有）

**输出**：
- 最终决策（买/卖/观望）
- 操作建议（买入金额/卖出数量/不动）
- 决策理由
- 归因链（因果分析）
- 反事实分析（假设场景）
- 风险提示

### 3.3 Web Dashboard

**功能**：
- 任务列表：显示所有分析任务
- 任务创建：选择市场分析或股票分析
- 任务详情：查看分析过程和结果
- 日志查看：实时查看 Agent 执行日志
- Workflow 解释：展示两个 Workflow 的详细流程图
- 批处理支持：股票分析支持批量提交多个股票代码

## 4. 技术架构

### 4.1 核心技术栈

| 组件 | 技术方案 | 说明 |
|------|---------|------|
| Workflow Engine | LangGraph | 多 Agent 编排，支持辩论循环 |
| LLM | 阿里云 DashScope + GLM-5 | 中文能力强，成本低 |
| 数据源-行情 | Akshare | 免费 A股数据 |
| 数据源-热点 | TrendRadar MCP | 新闻聚合，热点识别 |
| 推送 | 飞书 Webhook | 实时决策推送 |
| Web | FastAPI | 高性能 API 服务 |
| 存储 | SQLite + Workspace | 任务日志持久化 |

### 4.2 Agent 设计

**市场分析 Workflow**：
```
[宏观分析] -> [板块分析] -> [行业分析] -> [个股筛选]
```

**股票分析 Workflow**：
```
[Init] -> [基本面] -> [技术面] -> [汇总] -> [辩论] <-> [辩论] -> [Judge] -> [持仓建议] -> [推送]
```

## 9. 辩论机制详解

### 9.1 辩论轮数
- **最大轮数**：10轮（深度辩论）
- **提前终止**：连续5轮无新论据则停止

### 9.2 辩论评分
```python
SCORING_RULES = {
    "data_evidence": 10,      # 有数据支撑的论据
    "logical_argument": 8,    # 逻辑清晰的论据
    "counter_rebuttal": 6,    # 有效反驳对方
    "new_insight": 5,         # 提出新观点
    "weak_argument": -3,      # 论据薄弱
    "contradiction": -5,      # 自相矛盾
}
```

### 9.3 输出格式
- bull_score：买入方得分
- bear_score：卖出方得分
- debate_history：辩论记录
- consensus：是否达成共识

## 10. 归因与反事实

### 10.1 归因链格式

```
A(热点板块炒作) → B(龙头股关注度提升) → C(技术面突破信号) → D(基本面支撑) → E(买入建议)

每一步都有数据/论据支撑：
- A: TrendRadar 热度数据
- B: 龙虎榜/资金流数据
- C: akshare K线数据
- D: akshare 财务数据
- E: 综合评分 + 辩论结果
```

### 10.2 反事实推断

分析假设下跌场景：
- 下跌5%：短期波动，观望等待企稳
- 下跌10%：触发止损线，减仓50%
- 下跌20%：严重亏损，清仓止损
